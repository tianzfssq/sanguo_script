> 本文档描述项目所有"判断/检测"逻辑的当前实现。
> 修改检测相关代码时**必须同步更新本文档**（见根目录 AGENT.md）。

## 2. 场景判定（core/state.py）

### 2.1 判定顺序

```
detect()
 ├─ 1. 模板匹配判定 _match_scene()
 │     按 scenes.toml 顺序遍历：非 fallback 场景优先，fallback（主界面）最后
 │     命中任一场景 → 返回 (场景key, 置信度)
 └─ 2. 全部未命中 → 黑条回退 _bottom_black_ratio()
       底部 15% 区域黑像素占比 > 0.88 → settle（结算）
       否则 → map
```

- 场景在 toml 中的定义顺序就是判定顺序，**新场景要放在被它"包含"的场景之前**。
- `fallback = true` 的场景（仅 main）最后判定，防止抢占子场景。

### 2.2 单场景命中规则（_scene_matches）

1. **forbidden 排除**：任一排除元素命中 → 直接不算该场景；
2. **required 必需**：全部命中才算（各元素独立过置信度阈值）；
3. **默认模式**：未配置 required 时，任一元素命中即算该场景。

### 2.3 置信度

场景置信度 = 该场景所有元素匹配分的最大值（仅用于日志展示，不影响判定）。

### 2.4 黑条回退（仅区分结算/地图）

- 取窗口底部 `sample_bottom_ratio=15%` 区域，缩至 15% 后统计 RGB 均 < 40 的像素占比。
- `> settle_ratio(0.88)` → settle；否则 map。
- **历史教训**：主界面/战斗界面底部都是黑底面板（0.5~0.77），黑条无法区分战斗，
  战斗已改为模板判定（scene.battle），黑条只剩结算/地图二分。

### 2.5 诊断输出（detect_detail）

「检测当前场景」按钮使用明细版：逐场景打印每个元素的匹配分（忽略阈值探测，
含备选模板取最高）、required/forbidden 配置、命中的场景标注 `-> 判定命中`，
全部未命中时打印黑条占比。任务循环仍用静默 `detect()`，不刷屏。

## 3. 模板匹配（core/image_match.py）

- 算法：OpenCV `TM_CCOEFF_NORMED`，灰度匹配，只在游戏窗口截图内进行。
- **多模板**：Element 支持 `alt_templates`（备选模板列表），主模板 + 备选全部尝试，
  **命中任一即算命中**，取置信度最高者。用于同一按钮多种外观（如营地图标两种样式）。
- **多实例查找**：`find_all()` 返回元素全部命中位置（按 y 升序，邻近去重后保留得分最高者），
  用于同屏多个相同按钮的场景（如群雄竞技"选择对手"弹窗的 3 个"挑战"，取最靠下的=积分最低对手）。
- 多尺度：`scale_min ~ scale_max` 按 `scale_step` 步进（默认 1.0 即原尺寸）。
- 模板缺失/读取失败 → 该元素跳过（返回 None），不影响其他元素。
- 中文路径用 `np.fromfile + cv2.imdecode` 加载。
- **模板命名规范**：`首字拼音首字母_中文名.png`（如 `c_吃.png`、`z_主界面营地.png`、
  `l_领地鱼塘.png`）；同一元素多种外观用序号后缀（`z_主界面营地1.png`）。
- **历史教训**：小模板（约 18x17）极易误匹配（钓鱼小模板曾以 0.917 误中返回键），
  截模板时尽量带文字/边框取大块。

## 4. 场景配置总表（config/scenes.toml）

判定顺序 = 下表顺序（main 为 fallback 最后判）：

| 场景 | 判定规则 | 元素（模板 / 阈值） |
|---|---|---|
| camp_menu 营地弹窗 | 任一命中 | arena_entry = y_营地竞技场.png / 0.8 |
| arena 竞技场 | required: detect | detect=j_竞技场检测.png+alt j_竞技场检测1.png/0.8（右下"竞技场"页签：原模板为未选中暗底态，alt 为选中高亮态，均只截文字区域不带背景）, challenge1/2, exit_main; 另有 qunxiong_tab=j_群雄竞技.png、challenge_qx=t_群雄竞技_匹配.png（群雄逐鹿按键为"匹配"非"挑战"）、opponent_challenge=t_群雄竞技_挑战.png（"选择对手"弹窗内按键，同屏 3 个，均不参与判定，供自动打群雄竞技用） |
| arena_settle 竞技场结算 | 任一命中 | settle_detect = j_竞技场结算.png / 0.8 |
| battle 战斗 | required: auto + jinang | auto=z_战斗自动.png, jinang=j_战斗锦囊.png / 0.8；另有 auto_off=z_自动未开启.png / auto_on=z_自动开启.png（不参与判定，供工会 Boss 战斗开启自动用） |
| guild 工会 | 任一命中 | bargain=g_工会砍价.png（模板暂缺，元素跳过）, boss=g_工会boss.png+alt g_工会boss1.png（alt 为"公会BOSS"横幅文字，原模板带背景碎片仅 0.726 判不进）, challenge1=t_挑战1.png+alt g_挑战.png（Boss 面板挑战按钮为纯"挑战"文字，与竞技场带图标+次数的外观不同） |
| fishing 钓鱼小游戏 | required: detect | detect=d_钓鱼检测.png/0.8, fish=d_钓鱼.png（大模板防误匹配）, fish_remaining, fish_confirm, fish_icon, fish_gain |
| territory 领地 | 任一命中 | detect=l_领地检测.png/0.85（右上角"领地"标签，已按当前界面重截）, camp_entrance, pond（旧模板已失效，暂以 detect 单独判定） |
| main 主界面（fallback） | required: special + camp；forbidden: camp_menu.arena_entry | special=t_特惠.png/0.82（右侧金币袋按钮，已按当前界面重截——旧模板 0.63 导致主界面判不出、黑条回退误判为 map）, camp=z_主界面营地.png+alt z_主界面营地1.png/0.82；另有 guild/eat 等仅作点击入口不参与判定 |

**注意**：
- main 的 territory/guild/eat 元素**不参与判定**，仅作点击入口（进领地/进工会/连点定位）。
- **通用退出按钮（t_退出主界面.png）绝不能加入 guild 等场景的判定元素**：
  fishing 在判定顺序上晚于 guild，若 guild 含通用按钮会把钓鱼界面误判为工会。
  跨场景复用退出按钮时直接引用 `arena.exit_main` 元素（navigation._click_exit_twice 即如此）。

## 5. 导航判断（modules/navigation.py）

### back_to_main（返回主界面，各模块收尾用）

循环（每轮 1s，默认 20s 超时）直到 detect == main：

1. `battle/settle` → `battle.exit_settle()` 点击窗口底部退出结算；
2. 其他非主界面场景 → **点击退出按钮 2 次**（复用 arena.exit_main 模板，
   第 1 次点击后等 2s 再点第 2 次，应对"点一次只关一层弹窗"的情况）；
3. 退出按钮也匹配不到 → 静默等待重试直至超时。**不做 ESC 兜底**：
   游戏内按 ESC 无法返回主界面，且主界面误判时会造成无限按 ESC 刷日志。

### enter_scene（进入场景）

- **先检测当前场景**：不在主界面（如上次任务停留的竞技场）→ 调用 back_to_main
  点击退出按钮（红 X，t_退出主界面.png，已按当前界面重截）返回主界面，失败则放弃进入；
- 有 `[nav.paths]` 路径（如 arena = main.camp → camp_menu.arena_entry）：
  **每一步轮询等待元素出现并点击**（0.5s 间隔重试，菜单弹出前匹配不到会自动等），
  不依赖中间场景判定（曾因等 camp_menu 场景判定不命中而卡住不点竞技场）；
  最后一步点击后等待目标场景确认；
- 无路径：单步轮询点击 `main.<target>` 入口元素，再等待目标场景；
- 步骤场景无可用模板时按固定 1.5s 延迟兜底。

## 6. 战斗流程判断（modules/battle.py）

| 方法 | 判断逻辑 |
|---|---|
| `exit_settle()` | 无条件点击窗口底部中央（bottom-20px），sleep 1.5s。窗口未定位先自动定位 |
| `loop_until_settle()` | 挂机：A/D 交替长按移动，每 2s 检测一次，detect==settle 即退出结算 |
| `wait_battle_settle()` | 不动等待：settle → 退出返回 True；前 3s 后出现 arena/map 也算战斗结束（防刚点挑战误判） |
| `wait_battle_end_back(back_scene)` | **以"回到 back_scene"作为战斗结束标志**（战斗画面本身不做结束判定）；期间 detect ∈ exit_scenes（settle/arena_settle）就 exit_settle，默认 180s 超时 |

关键设计：竞技场/工会 Boss 的战斗结束不依赖黑条，以"挑战按钮所在界面重新可见"为准。

## 7. 业务模块流程判断

### 自动打竞技场（arena.py）

循环（settings `[arena].max_rounds` 默认 5，0=不限）：
1. detect ∈ (settle, arena_settle) → exit_settle；
2. 非 arena 场景 → 重新 enter_scene("arena")；
3. 依次尝试点击 challenge1 → challenge2，**两个都点不到 = 次数用完，结束**；
4. `wait_not("arena", 10s)` 以"离开竞技场"确认进入战斗；
5. `wait_battle_end_back("arena")` 等回到竞技场；
6. finally：back_to_main。

### 自动打群雄竞技（qunxiong.py）

与自动打竞技场基本一致（settings `[qunxiong].max_rounds` 默认 5，0=不限），区别：
1. 入口相同：enter_scene("arena")（主界面 → 营地 → 二级菜单 → 竞技场）；
2. 每轮点挑战前先确保已切玩法：challenge_qx 不可见 → 点击 qunxiong_tab
   （j_群雄竞技.png，"群雄逐鹿"页签未选中暗底态）→ 等 2s，复检未出现则补点一次；
3. 点「匹配」= challenge_qx（t_群雄竞技_匹配.png，按键为"图标+次数+匹配"），
   点不到 = 次数用完结束；
4. 弹出"选择对手"弹窗（最多等 8s）：`find_all` 命中 3 个"挑战"
   （opponent_challenge = t_群雄竞技_挑战.png），**点击最靠下的一个**（对手积分最低）；
5. 之后 wait_not / wait_battle_end_back / finally back_to_main 与竞技场相同。

### 自动打工会boss（guild.py）

rounds 次（settings `[guild].rounds` 默认 2）：
1. enter_scene("guild")；每轮开始 detect ∈ SETTLE_SCENES 先退出结算、非 guild 重新进入；
2. `need_open` 标志：**仅首轮点 boss 按键打开挑战面板**（战后停在挑战面板，无需再开）；
   重新进入工会后重置为 True；
3. 点挑战前先检测 challenge1 可见性：不可见则点底部关弹窗再检测，
   **连续 3 次 + 兜底 1 次仍不可见才判失败**；
4. `wait_not("guild", 10s)` 确认进入战斗 → `_enable_auto_battle()`：
   检测 battle.auto_off（z_自动未开启.png，暗底"自动"文字）可见则点击开启，
   点击后 1s 用 battle.auto_on（z_自动开启.png，亮底）复检是否点亮，未点亮补点（最多 2 次，
   防偶发丢点击）；若 auto_on 可见或 3 次×2s 未检出则跳过（不参与场景判定）；
   之后 `wait_battle_end_back("guild")`；
5. finally：back_to_main。

### 钓鱼（fishing.py）

1. `_is_scene("territory")`（匹配 territory.detect 元素）判断是否在领地，不在先进入；
2. 固定按键序列移动：S×4（进营地）→ 按住 A 4s → 按住 W 3s；
3. 点鱼塘用**固定坐标**（settings `[fishing].pond_pos` 默认 200,345，窗口内相对坐标）；
4. 每轮：点 fish → 等 4s → 点 fish_confirm（进入钓鱼游戏的确定键）→
   等 fish_gain（获得奖励）15s 超时 → **退出结算用简单法：点底部 1 次 → 等 1s → 再点 1 次**
   （曾尝试检测 fish_confirm / fish_icon 判定退出，均不可靠后弃用）；
5. 循环 `[fishing].fish_times`（默认 10）次。

### 每日任务（daily.py）

顺序串联：ArenaAutoModule → QunxiongAutoModule → GuildBossModule → FishingModule
（各自收尾回主界面），每步前检查 stop_event，最后统一 back_to_main。

### 连点（clicker.py）

定位 `main.eat` 元素一次 → 窗口置前、鼠标移到目标 → 循环
按下 50ms / 松开 50ms（pynput MouseController，不受 pyautogui 全局 PAUSE 影响）。
退出条件：按 `` ` `` 键（pynput 全局键盘监听，char=='`' 或 vk==192 双判定）或停止信号；
**finally 中若仍处按下状态补发松开**。

## 8. 界面工具（ui/panel.py）

- 「停止任务」/ 停止热键 `~`：TaskRunner 在任务运行期间注册全局键盘监听（pynput），
  按 `~`（与 `` ` `` 同一物理键，vk=192 兜底兼容中文输入法）即发送停止信号，
  与点击「停止任务」按钮等价；任务结束（含异常）自动注销监听。
  连点模块按 `` ` `` 退出连点的同时也会触发任务停止，行为一致。
- 「检测当前场景」：调用 `detect_detail()`，打印逐场景元素得分明细（见 2.5）。
- 「测试：模板查找」：输入模板文件名（自动补 .png、取纯文件名），
  用 confidence=0 的探测元素匹配当前窗口截图，输出真实最高得分与坐标
  （窗口内坐标 + 屏幕绝对坐标），≥0.8 报"找到"，否则报最高得分。
  `ImageMatcher.templates_dir` 属性为面板提供模板目录。

## 9. 历史经验（避免重复踩坑）

1. **小模板误匹配**：18x17 的钓鱼小模板曾 0.917 误中返回键 → 换带文字大模板。
2. **通用按钮不能进场景判定**：见第 4 节注意事项（guild 不能含 exit_main）。
3. **黑条不能区分战斗**：主界面 0.5 / 战斗 0.77 / 结算 >0.88，只有结算可判。
4. **主界面模板需随版本更新**：界面改版后 camp/guild/territory 旧模板全部失效，
   required 过严会导致掉入黑条兜底误判 battle。现判定收敛为 特惠 + 营地（双模板）。
5. **pynput 特殊键**：字符串 "esc" 直接传会抛 ValueError，需经 `_SPECIAL_KEYS` 映射。
6. **WebView 输入时序**：点击需按住 ≥80ms，短按键需按住 50ms，否则游戏不响应
   （详见 docs/keyboard-simulation-lessons.md）。
7. **结算弹窗可能连续 2 个**：工会/竞技场用"检测→点底部重试"，钓鱼用"无条件点 2 次"。
8. **模板裁剪严禁带背景/临时元素**：`j_竞技场检测.png` 裁剪时带了页签背景，页签从
   未选中暗底变为选中亮黄后仅 0.554，进竞技场判定失败（guild 还因复用 t_挑战1.png 被误判命中）。
   裁模板只截目标自身特征区域（文字/图标），避开背景、红点、高亮描边；同一目标有多种
   外观状态时每种状态各裁一个并配 alt_templates。规范见 AGENT.md「模板裁剪规则」。
