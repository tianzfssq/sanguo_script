# 三国小游戏自动挂机 — 功能扩展需求文档

## 1. 概述

在现有自动挂机打怪脚本的基础上，扩展为功能完整的自动化助手，覆盖主界面、领地地图、竞技场、工会等核心玩法，并提供可视化操控面板。

---

## 2. 现有基础

| 项目 | 说明 |
|------|------|
| 脚本 | `auto_battle.py` — 窗口定位 → 前台聚焦 → A/S 移动遇敌 → 底部黑条检测结算 → 自动退出循环 |
| 核心技术 | `win32gui` 窗口定位、`pynput` 按键模拟、`PIL` 像素采样、`pyautogui` 截图/点击 |
| 已知约束 | 微信小游戏底层是 Chromium WebView，按键模拟需同时提供 VK 码 + 扫描码（pynput 已满足） |

## 4. 架构设计

### 4.1 分层架构

```
┌─────────────────────────────────────────┐
│              GUI 层 (ui/)                │
│  Tkinter 面板：按钮、状态、日志           │
├─────────────────────────────────────────┤
│          编排层 (orchestrator/)          │
│  任务调度：启动/停止、状态机、错误处理     │
├─────────────────────────────────────────┤
│          模块层 (modules/)               │
│  arena | guild | territory | fishing ... │
├─────────────────────────────────────────┤
│          核心层 (core/)                  │
│  window | image_match | input | state    │
└─────────────────────────────────────────┘
```

### 4.2 核心层（core/）

| 模块 | 职责 | 说明 |
|------|------|------|
| `window.py` | 窗口定位与激活 | 复用现有 `find_game_window()` / `focus_window()` 逻辑，封装为类 |
| `image_match.py` | 图像模板匹配 | 基于 OpenCV `cv2.matchTemplate`，支持截图 → 匹配模板 → 返回坐标+置信度 |
| `input.py` | 输入模拟 | 封装 pynput 键盘 + pyautogui 鼠标操作，提供 `click(x,y)` / `press_key()` / `wait_click()` 等 |
| `state.py` | 状态检测 | 封装现有底部黑条检测，扩展为通用画面状态检测（战斗中、结算、地图、主界面等） |
| `screen.py` | 截图工具 | 窗口区域截图，支持全屏/局部截图，返回 PIL Image 或 numpy 数组 |

### 4.3 模块层（modules/）

| 模块 | 职责 |
|------|------|
| `arena.py` | 竞技场自动化：挑战对手、检测胜负、循环 |
| `guild.py` | 工会自动化：砍价、打 Boss |
| `territory.py` | 领地任务自动化：导航、接取/完成任务 |
| `daily.py` | 日常自动化：锻造、钓鱼、烹饪 |
| `fishing_game.py` | 钓鱼小游戏：进度条识别、时机判定 |
| `navigation.py` | 通用导航：返回主界面、进入指定场景 |

### 4.4 编排层（orchestrator/）

| 模块 | 职责 |
|------|------|
| `task_runner.py` | 任务执行器：接收任务指令，管理执行生命周期，处理超时/异常 |
| `state_machine.py` | 状态机：维护当前所在场景（主界面/领地/竞技场/工会/未知），驱动场景切换 |

### 4.5 模板管理

- 目录：`templates/` — 存放各功能入口的截图模板（PNG）
- 命名规范：`{场景}_{功能}.png`，如 `main_arena.png`、`main_guild.png`、`territory_fishing.png`
- 模板需用户首次运行时通过"截图采集模式"自行截取，以适应不同分辨率/设备

## 5. 关键技术方案

### 5.1 图像模板匹配

```
截图 → 灰度化 → cv2.matchTemplate(截图, 模板, TM_CCOEFF_NORMED)
     → 置信度 > 阈值(0.8) → 返回中心坐标 → pyautogui 点击
```

- 依赖：`opencv-python`
- 场景切换后等待 0.5~1s 再截图，确保 UI 渲染完成
- 支持多尺度匹配（缩放模板 ±10%），适应窗口尺寸微调

### 5.2 场景状态检测

在现有 `detect_state()` 基础上扩展：

| 场景 | 检测方式 |
|------|----------|
| 主界面 | 模板匹配多个特征按钮（领地、竞技场、工会等），任一命中即确认 |
| 领地地图 | 模板匹配领地特有 UI 元素（小地图、任务列表等） |
| 竞技场界面 | 模板匹配竞技场特有 UI（挑战按钮、排名等） |
| 工会界面 | 模板匹配工会特有 UI（砍价按钮、Boss 入口等） |
| 战斗中 | 现有底部黑像素检测（~76% 黑） |
| 结算画面 | 现有底部黑像素检测（~98% 黑） |

### 5.3 任务调度

- 每个功能模块实现 `run()` 接口，返回成功/失败/超时
- 编排层通过 `TaskRunner` 管理：启动任务 → 监控状态 → 处理异常 → 清理
- 停止信号通过 `threading.Event` 传递，支持优雅中断
- 所有自动化操作运行在独立线程，不阻塞 GUI

### 5.4 GUI 设计

- 框架：Tkinter（Python 标准库，零额外依赖）
- 窗口置顶：`root.attributes('-topmost', True)`
- 布局：左侧按钮区 + 右侧日志区
- 按钮分为三组：导航类、自动化类、控制类
- 日志区滚动显示最近 50 条操作记录，带时间戳

## 6. 模板采集模式

首次使用或分辨率变更时，用户需采集模板：

1. 点击 GUI 的"采集模板"按钮进入采集模式
2. 程序提示"请将鼠标移动到 {功能名} 按钮上，按 Space 截图"
3. 用户对准后按 Space，程序以鼠标为中心截取 60×60 区域
4. 保存为 `templates/{场景}_{功能}.png`
5. 重复直到所有模板采集完毕

或采用简化方案：用户手动截图放到 `templates/` 目录，程序启动时校验模板是否存在。

## 10. 风险与注意事项

1. **模板匹配精度**：不同设备/分辨率下 UI 可能略有差异，需支持多尺度匹配和模板重采集
2. **网络延迟**：游戏操作后需等待服务器响应，操作间隔需可配置
3. **弹窗干扰**：游戏中可能弹出活动/公告等干扰窗口，需兜底检测并关闭
4. **微信小游戏窗口变化**：微信版本更新可能导致窗口类名变化，需持续关注
5. **线程安全**：GUI 与自动化线程间的数据交互需加锁保护
6. **反作弊风险**：自动化操作需模拟人类操作节奏（随机延迟），避免被检测
